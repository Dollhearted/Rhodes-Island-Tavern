# 酒馆自走棋（八人对局）

运行 `python server.py`，打开 `http://127.0.0.1:11451`，输入昵称后开始。

## 对局规则

- 1 名玩家与 7 名 AI 各自经营商店、7 格棋盘及 12 格手牌，共享本局卡池。不同游戏的卡池相互独立。
- AI 通过和玩家相同的购买、出售、升级、上场、技能及三连流程经营，不再生成随回合膨胀的敌方属性。七名 AI 综合战力、升本、经济、阵营配合，侧重点各不相同；目前使用规则评分，不收集历史对局训练数据。
- 开局 50 生命、3 金币；后续基础补给为 4、5、6……，上限 10；胜利无额外金币，技能收入不封顶。商店升级基础价格与逐回合减免规则不变。
- 每轮存活者两两交战，优先匹配交手次数较少的对手；存活人数为奇数时，加入排名最高的已淘汰玩家的冻结阵容。
- 配对在备战开始时确定，对手头像缓慢闪烁；升级商店时头像下方以骰子排列的黄色星星提示新等级，点击头像可实时查看商店等级。
- 战败扣血为胜者商店等级加战斗结束时存活棋子的总星级。按本轮开战时的存活玩家数统一判断：超过 4 人时上限为 15，4 人及以下不设上限，平局不扣血。
- 后淘汰者排名更高；同轮淘汰时，剩余生命（可为负数）较高者排名更高。玩家淘汰或七名 AI 全部淘汰时结束，仍存活的 AI 按剩余生命排列。结算展示全部八人的排名、阵容与属性，不计分、无 14 轮上限。
- 备战主界面只有商店、棋盘及手牌。商店上方头像按生命排序，细圆环显示生命占 50 的比例。点击任意头像只显示上一轮结束时的公开阵容，不显示本轮经营变化。战斗期间临时显示实际对手棋盘。
- 第 1–3 轮备战 30 秒，第 4–5 轮 45 秒，第 6–7 轮 60 秒，第 8 轮起 90 秒。提前结束备战时，AI 仍会完成本轮正常经营。
- 新手教程保持独立，不使用八人共享卡池。运行中的经营状态由页面持有，请勿中途刷新；刷新后重新开始新局。
- 开始界面和游戏左上角均有“推荐阵容”：可查看各阵营的成型阵容、过渡卡和运营说明，维护者本机可编辑保存（服务器共享存储，发布版只读）。AI 从下一轮备战读取方案，根据已持有棋子选择路线，以成型卡、过渡卡和站位顺序指导经营；这是规则评分参考，不是历史数据模型训练。

## 实现与验证

`arena.js` 负责八人界面和 AI 决策，通过独立页面环境复用现有玩家规则。`server.py` 负责共享卡池、配对、双方战斗、快照及排名，并使每轮结算幂等，避免重复发放收入。

回归检查：`python -m unittest test_arena test_sales test_bullet_batches -q` 和 `node test_frontend.cjs`。
## 数据库

- `schema.sql` 是棋子配置的唯一数据源，使用 UTF-8 保存中文名、阵营、星级、攻击、血量、普通/金卡描述与机制 JSON。
- `server.py` 启动时执行 `schema.sql`，将棋子配置同步至 `data/autochess.sqlite` 的 `unit_cards` 表。
- `players` 表继续保存本地玩家的金币、生命、回合、商店等级与升级减免。
- 修改棋子时编辑 `schema.sql` 并重启服务即可，不再需要修改 `server.py` 中的棋子常量。

核心服务逻辑位于 `server.py`：`buy_card()`、`tavern_battle()`、`arena_pairings()` 和 `arena_resolve()`。数据库结构见 `schema.sql`。

## 部署：保护服务器存档

`data/autochess.sqlite` 是**运行时数据**，里面存着服务器上所有玩家的金币、生命、回合与商店等级。它已在 `.gitignore` 中整目录忽略（`data/`），且从未被 git 跟踪，因此：

- `git pull` 只更新被跟踪的源码文件，**不会删除也不会覆盖**服务器上的存档；
- 首次部署时 `server.py` 会自动 `mkdir data/` 并用 `schema.sql` 建库，所以仓库里不需要预置空存档；
- 请**不要**用 `git add -f` 强行提交 `data/` 下的任何文件，那会让本地存档在服务器上覆盖线上存档。

备份线上存档时直接复制该文件即可（SQLite 单文件）：

```bash
cp data/autochess.sqlite data/autochess.sqlite.bak.$(date +%F)
```

`.gitignore` 同时忽略了 `*.sqlite` / `*.db` / `*.sqlite-*` / `*.db-*` / `saves/` 等模式，
所以即使把存档或备份放到 `data/` 以外的位置，也仍然不会被误提交。
部署前可用 `git add -A --dry-run` 确认待暂存清单里没有存档。

## 界面与立绘

- 界面采用移植适配后的 Stronghold-Protocol 视觉体系：近黑绿灰底、薄荷绿交互色、金色经济提示、括角按钮、雷达扫描与点阵徽记；保留本游戏的阵营配色、星级和机制图标。桌面宽屏使用左侧敌我棋盘、右侧商店、底部备战区布局。
- 每张棋子卡的卡面即该干员的立绘，取自 `assets/精二立绘/`（`_manifest.json` 为素材清单）。立绘映射表是 `index.html` 中的 `const ART={...}`，键为 `unit_cards.id`，覆盖当前全部棋子。
- 卡面结构：立绘 + 左上阵营标签 + 右上六边形星级标 + 等宽 `ATK / HP` 数据条 + 中文名牌与生命条；金卡为暖金描边，技能卡不配立绘，走几何切分版式。
- 稀有度统一按星级取色：I 灰、II 蓝、III 紫、IV 金、V 橙、VI 红，同时用于卡框、左侧色条与准星。
- 皮肤源文件与注入/检查脚本存放在 `.workbuddy/tmp/`，改皮肤的流程见 `.workbuddy/tmp/README.md`。

## AI 自对弈训练

启动或重启 `python server.py` 后，在浏览器中打开
`http://127.0.0.1:11451/train-ai.html`（服务器部署时使用对应域名）。
设置代数和每代局数，点击开始；建议先用 1 代 × 1 局试跑，再使用 10 代 × 3 局或更多。
八个独立 AI 共用卡池，沿用真实购买、技能、三连、战斗规则；训练独立对局不会覆盖人类玩家存档。
训练必须保持页面打开，后台标签页可能被浏览器节流。

这是六个经营参数的进化搜索，并非神经网络训练：即时战力、升本倾向、经济、阵营配合、核心卡和过渡卡权重。
每代保留一个优胜参数组，并产生七个变体，多局轮换座位和购买顺序降低先后手偏差。
奖励为推荐阵容多重集匹配度 45%、棋盘攻击和最大生命总和的对数归一化 35%、最终名次 20%；
匹配按七个位置计，重复核心需相应重复棋子，不计手牌。
淘汰者使用淘汰时保留的阵容；八人对局直到决出胜者，100 回合安全上限及手动停止的未完成代不更新参数。
不同代的随机对局不完全相同，评分不能直接作为胜率提升证明。

每代结果保存于服务器训练表，保留最近 100 代的参数、分数、对局指标和推荐阵容快照，支持下载 JSON。
点击“应用优胜参数到游戏”更新服务器共享参数，新开对局的 AI 自动使用该参数；不会自动替换原有策略。
更改推荐阵容后可继续训练，当前一批训练中推荐阵容快照保持固定。


推荐阵容现通过 `/api/guides` 保存在服务器 SQLite 的 `shared_guides` 表中。同一服务器的所有浏览器共用；重新打开推荐阵容窗口获取最新版本。首次打开会合并该浏览器旧打法，同 ID 不同内容另存一套，原 localStorage 保留备份。并发编辑同一打法会提示冲突，避免覆盖。发布版推荐阵容只读，维护者本机通过未提交的本地配置开启编辑。AI 每轮备战读取服务器方案；训练每批固定快照。训练参数和训练记录也已改为服务器共享。

删除共享阵容：`POST /api/guides`，JSON 为 `{"mode":"delete","id":"阵容 ID","revision":1}`；revision 使用 GET 列表返回的版本。界面提供“删除阵容”按钮。删除保留墓碑记录，旧浏览器迁移和过期编辑不会使已删除阵容重新出现；阵营列表允许为空。


训练共享更新：`GET /api/training` 返回服务器 checkpoint、policy、revision；POST 支持 save（携带 checkpoint、revision）、apply（携带 revision）和 import（只补充服务器空数据）。训练页面每代保存到服务器，AI 在新对局初始化时读取共享 policy。旧浏览器本地记录首次打开训练页时自动补充到空服务器，原记录保留；服务器已有数据不被迁移覆盖。同时训练的过期保存会拒绝，本次结果保存在 `autochess-training-unsynced`，页面仍可导出。训练参数与推荐阵容均为同一服务器共享；推荐阵容编辑仅维护者本机开启。需重启 server.py 加载新接口。


## version3.0 发布数据与本地编辑

`release-defaults.json` 随仓库发布当前推荐阵容及第 15 代已应用 AI 参数和训练记录；新数据库首次使用时自动导入。已有服务器数据不会被覆盖。游戏中的所有浏览器从同一服务器读取已应用参数，新对局生效。

发布版默认推荐阵容只读，隐藏新增、编辑和删除按钮，POST `/api/guides` 返回 403。维护者本机的 `data/owner-edit.json` 为 `{"enabled":true}`，仅本机回环连接允许更新，跨站 Origin 请求拒绝。该配置和整个运行时数据库不入库，HTTP 禁止访问 data/、隐藏文件和目录列表。公开源代码允许下载者自行修改其副本，因此这里限制的是默认发布版接口，不是禁止别人修改源码。

本次提交导出阵容和模型快照，不提交玩家存档、私有配置或整个数据库。更新 Python 后需重启服务。
